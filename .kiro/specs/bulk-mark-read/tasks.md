## Implementation Notes

- `npx tsx scripts/lint-no-japanese.ts` は本機能の着手前(HEAD 時点)から失敗している。原因は `add-issue-templates` ブランチが追加した `.github/ISSUE_TEMPLATE/*.yml` と `.devcontainer/default/Dockerfile` の日本語で、本機能とは無関係。各タスクの合否は「自分が変更したファイルの違反がゼロであること」で判定する。許可リストに含まれるのは `src/lib/i18n.ts`、`src/lib/demo/i18n.ts`、`*.test.ts`/`*.test.tsx`、`src/lib/demo/seed/`、`*.json` など。新規のソースファイルに書くコメントと文字列は英語にする。
- 設計書の TypeScript 定義に付いている日本語のドキュメントコメントは、そのまま写すとリントに違反する。実装時は英語に訳して入れる。
- libsql のバインドパラメータ上限は実測で 32766(32767 で `too many SQL variables`)。親コントローラが直接測定して確認済み。当初「2000」と記録したが誤りだった。分割処理の検証テストは対象件数を 32766 件超にしないと、分割を外しても通ってしまう。タスク 2.1 の 1201 件のテストは分割処理を証明できていないため、タスク 6.2 で 32766 件超の検証を行う。
- `server/db/index.ts` は関数の名前付きエクスポートのみを列挙している。型を `server/db.ts` 経由で import すると TS2305 になる。ルート層は `shared/types.ts` の `RangeSeenResponse` を使う。
- `published_at` は ISO-8601 UTC 文字列で保存されるため辞書順と時系列順が一致する。`getArticles` も同じ列を同じ比較で並べており、方向述語は構造的に表示順と一致する。
- タスク 2.2 のレビューで、更新文の分割ループを無効化してもテストが通る穴が見つかった(SELECT 側の分割は 40002 件のテストで証明済み)。実在行を 33000 件作るテストは vitest ワーカーが落ちるため、タスク 6.2 で別手段を検討する。
- 取り消しのスコア同期は対象1件ごとに検索インデックスへ1回ずつ送信する。上限 50000 件では負荷が大きい。バッチ化には `server/search/sync.ts` の変更が必要で本仕様の境界外のため、将来の課題として記録する。
- このコンテナは利用可能メモリが 1GB 前後まで下がることがあり、`npm run lint` と `npm run typecheck` が終了コード 137(OOM による強制終了)で落ちる。テストも道連れで失敗する。コードの問題ではないため、失敗したらメモリ回復を待って再実行する。日常の検証はファイル単位の `npx eslint <path>` を使い、全体のリントは最終検証でまとめて確認する。
- ルート層の `range-seen` には件数上限がなく `batch-unseen` は 50000 件で上限を設けている。応答の ID が 50000 件を超えると取り消しが 400 になる。設計の Risks で許容済み。
