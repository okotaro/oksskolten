  - _Depends: 1.1_
  - _Boundary: markAllSeenByFeed_

- [ ] 2. クライアント: ローカル反映口、実行ロジック、ボタン
- [ ] 2.1 (P) 記事一覧に既読状態をローカルへ即時反映する操作を公開する
  - 記事一覧が既に持っている「再取得せずに既読の見た目を反映する」ローカル状態に対して、指定した記事ID群を追加する操作と取り除く操作を、ページ側から呼び出せる形で公開する
  - 既存のスクロール自動既読・記事単位の一括既読が使っているローカル状態と同じ状態を共有し、別の状態層を作らない
  - ページ側から対象記事IDを渡して呼び出すと、対応する記事が再取得なしに既読の見た目へ切り替わる状態になる
  - 取り消し操作で呼び出すと、対応する記事が既読の見た目から元に戻る状態になる
  - _Requirements: 3.1, 4.5_
  - _Boundary: ArticleListHandle_

- [ ] 2.2 (P) 全件既読の実行・通知・取り消しを行うフックを実装する
  - フィード対象またはフォルダ対象を受け取り、対応する全件既読の処理を確認操作なしに即座に呼び出す
  - 成功し対象記事が1件以上あれば、対象記事をローカルの既読表示へ反映するコールバックを呼び、未読件数を提供するキーのみを再検証する。記事一覧そのものを再取得する再検証は行わない
  - 対象記事が1件もない場合は取り消し手段のない通知のみを出す
  - 件数が1件以上のときは、取り消し操作付きの通知を少なくとも10秒間表示する
  - 取り消しでは、応答に含まれていた対象記事IDをそのまま未読化処理に渡し、成功時はローカルの既読表示を元に戻す。失敗時はローカルの既読表示を既読のまま維持する
  - 既読化そのものが失敗した場合は、失敗を通知し記事の見た目・未読件数を操作前のまま維持する。通信不可の状態も同様に即座に失敗として扱い、保留や再試行は行わない
  - 実行中に同じボタンへの重複した呼び出しがあっても、二重にリクエストを送らない
  - 成功(件数あり)、成功(0件)、失敗、取り消し成功、取り消し失敗、重複呼び出しの各経路が単体テストで通る状態になる
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 3.2, 3.3, 4.1, 4.2, 4.3, 4.4, 4.6, 5.1, 5.2, 5.3_
  - _Depends: 1.1_
  - _Boundary: useMarkAllRead_

- [ ] 2.3 既読化ボタンのUIコンポーネントを実装する

  - 実行中はボタンを無効化し、見た目の上でも重複クリックを防ぐ
  - 対象を指定してクリックすると実行ロジックが呼ばれ、実行中はボタンが無効化される状態がコンポーネントテストで確認できる
  - _Requirements: 1.5, 2.4_

## Implementation Notes

- `.claude/rules/docs.md`により、機能追加時は`docs/spec/*.md`(英語)の更新、利用者から見える変更であれば`README.md`への要約追記、および`make lint-docs`での検証が求められる。kiroのタスク生成ルールはドキュメント作業をタスクから除外しているため、承認済みタスクにこの作業は含まれていない。全タスク完了後に別途対応すること。
- `.claude/rules/language.md`により、新規のソースファイルに書くコメント・ログ・エラーメッセージは英語にする。i18n辞書(`src/lib/i18n.ts`)とテストファイルは日本語を含められる既存の許可対象。
- サーバー側は`shared/types.ts`の型を`import type`で参照する既存パターン(例: `BulkReadDirection` / `BulkReadScope`)に倣う。
